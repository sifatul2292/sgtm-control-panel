Getting Started

Every Tagioo account starts on the Free plan (15,000 events/month, forever). Launch flow, top to bottom:

  • Create your Tagioo account and a GTM Server container
  • Point a subdomain at Tagioo via one CNAME record
  • Create a container in your Tagioo dashboard
  • Generate and import Web + Server GTM templates via Setup Assistant
  • Connect your store (WooCommerce plugin or the self-service Laravel Bridge)
  • Test in Meta Events Manager and confirm events in your dashboard

See the full step-by-step walkthrough for screenshots and detail on each step.

WooCommerce Plugin

Download the Tagioo plugin from your dashboard's Setup Assistant, upload it under Plugins → Add New → Upload Plugin in WordPress, activate, and paste your container's tracking ID when prompted. No GTM4WP or manual dataLayer coding needed.

Once active, it automatically pushes these events to the dataLayer on every relevant page:

  • page_view — every page load, with page_location and page_title set explicitly
  • view_item — product page views
  • add_to_cart — cart additions, with product ID, price, quantity
  • begin_checkout — checkout page reached
  • purchase — completed order, with transaction ID, value, and items
  • Hashed user_data (email, phone) on purchase for Meta CAPI match quality, where available

Laravel Setup

Laravel stores use Tagioo's generated GTM templates for browser events and a private cPanel Bridge for reliable backend Purchase tracking. The standard installation needs no Composer, terminal, Laravel code changes, VPS access, or hosting-password sharing.

Before you start

  • A live Tagioo container and first-party tracking domain
  • Your store URL and Web GTM container ID, such as GTM-XXXXXXX
  • cPanel access with File Manager and Cron Jobs
  • PHP 8.1 or newer on the Cron command line

Add only the Web GTM ID to the Laravel website. The Server GTM container runs through Tagioo and is never pasted into the website.

1. Generate and import the GTM templates

  1. Open Setup Assistant and select Ecommerce → Laravel / Custom Ecommerce.
  2. Confirm the currency, tracking domain, and only the destinations you actually use. Add the required IDs, tokens, and test codes for those destinations.
  3. Generate the Web and Server container files.
  4. Import tagioo-web-template.json into Web GTM and tagioo-server-template.json into Server GTM.
  5. For a first import, choose Merge. When replacing an older Tagioo setup, choose Merge → Overwrite conflicting tags, triggers, and variables.
  6. Keep both containers in Preview mode until the complete test below passes.

The Web template tracks browser activity such as PageView, ViewContent, AddToCart, and InitiateCheckout. The Bridge supplies the authoritative backend Purchase, including orders missed by browser blockers, redirects, or a closed confirmation page.

2. Install the private cPanel Bridge

  1. Enter the public store URL in the Laravel setup and download the private Bridge ZIP.
  2. Open cPanel → File Manager, go to the account home directory one level above public_html, upload the ZIP, and extract it.
  3. Confirm the resulting tagioo-bridge folder is outside public_html.
  4. Open README.txt inside the package and copy its complete Cron command.
  5. Open cPanel → Cron Jobs, select Once Per Minute, paste the complete command, and save it.
/usr/local/bin/php /home/CPANEL_USERNAME/tagioo-bridge/bridge.php run

Use the exact PHP path and cPanel username shown by the package or hosting account. If Cron Jobs is unavailable, ask the hosting company to schedule the supplied command once per minute. Root or VPS access is not required.

3. Confirm detection and mapping

Wait up to two minutes, return to Tagioo, and click Check connection. The Bridge sends table and column names for detection—not database credentials, customer records, or passwords.

If the status is Needs mapping, open Advanced mapping and review the orders table, public Order ID, total, status, timestamps, items table, item reference, product ID/name, price, quantity, and valid order statuses.

  • For Order ID, prefer the customer-facing invoice or order number, such as invoice_id, invoice_number, or order_number, instead of an internal database id.
  • For COD stores, include the status created for a valid placed order. It may be a word such as pending or a numeric value such as 1.
  • Save the mapping and wait for the next Cron run. Tagioo will then show Ready or Active.

Click Activate tracking only after the mapping is correct. Activation checkpoints existing orders, so the Bridge tracks new orders instead of importing the store's history.

4. Complete and verify one test order

  1. Start GTM Preview for both Web and Server containers.
  2. Place one new order through the normal storefront after tracking is activated.
  3. Make sure the order reaches one of the configured valid statuses.
  4. Wait up to two minutes, then click Verify test order in Tagioo.
  5. Confirm the public order ID, amount, currency, items, and selected destinations.
  6. Publish both GTM containers only after the test passes.

5. Check Meta browser/server deduplication

In Meta Events Manager, open Test events, enter the test code used in Tagioo, clear old activity, and perform a fresh journey. Browser and Server rows are expected. For one logical event, their event name and Event ID must match; Meta normally marks one copy as Deduplicated.

Tagioo-created Event IDs begin with tagioo- for funnel events, while Purchase uses the mapped public order ID. An ID beginning with something else—such as ob3_plugin-set_—comes from another script installed on the Laravel website, not from Tagioo.

Existing Meta or TikTok tracking

Keep the store's standard ecommerce dataLayer pushes, but disable old GTM tags or hard-coded fbq('track', ...), fbq('trackCustom', ...), and ttq.track(...) calls that send the same events directly. Two independent browser senders use different Event IDs and cannot be deduplicated correctly.

Safety, pausing, and removal

The Bridge uses read-only database SELECT queries, does not edit Laravel source files, does not run migrations, retries temporary network failures, and deduplicates orders by store and Order ID. Keep the ZIP, config.php, and its secret outside public_html and never share them.

Use Pause tracking in Tagioo to stop new Bridge purchases. For an immediate local stop, disable the Cron Job. Removing the Cron Job and tagioo-bridge folder removes the Bridge without changing the Laravel website.

GTM Setup Assistant

Prefer to follow along? Watch the complete Tagioo server-side tracking setup video ↗.

A 4-step wizard in your dashboard that generates two ready-to-import JSON files:

  • web.json — imports into your Web GTM container: dataLayer listeners, the Custom Loader tag, and Consent Mode v2 defaults
  • server.json — imports into your Server GTM container with the server tags and credentials required by the destinations selected in the assistant

For a first import, use Import Container → Merge. When updating an existing Tagioo setup, use Merge → Overwrite conflicting tags, triggers, and variables. Review in Preview mode, then Publish both containers.

First-party Domain & SSL

Point a subdomain you own at Tagioo with a single CNAME record:

track.yoursite.com CNAME bd.tagioo.com

Once DNS propagates (usually minutes, sometimes up to a few hours), Tagioo automatically provisions an SSL certificate via Let's Encrypt and renews it silently — no action needed from you. This is also the domain the Custom Loader uses to serve gtm.js/gtag.js first-party, which is what lets tracking survive Brave and most ad-blockers.

Offline Conversions

Available on Pro and Enterprise. Upload a CSV of phone, COD, or in-store orders from your dashboard's Offline Conversions view. Expected columns:

order_id, value, currency, email, phone, event_time

Email and phone are hashed client-side before upload. You'll see a validation preview before confirming, and every upload is logged with a per-batch history so you can see exactly what was sent to Meta CAPI and when.

Purchase Gap Alert

Tagioo compares today's purchase count against your trailing 7-day average, scaled for time of day so it doesn't false-positive at 9am. If today's count runs more than 50% below that baseline, a red banner appears in your dashboard the same day — instead of you noticing days later via a bad ROAS number.

On the Free plan, usage against your 15,000 events/month cycle is tracked the same way: you're notified by email and WhatsApp as you approach the limit (at rising thresholds from 10K events), and your container pauses if you reach 15,000 until the 30-day cycle resets or you upgrade.

Troubleshooting

Events not showing up in Meta Test Events? Confirm your Server GTM container is published (not just saved), check the container status in your Tagioo dashboard is "Running," and verify your domain's SSL certificate is issued (a padlock on https://track.yoursite.com).

Purchases missing after a WooCommerce order? Check the WordPress plugin is active and its container tracking ID matches your dashboard. Use the Purchase Inspector in your dashboard to search by order ID and see exactly which destinations (Meta, GA4) received it.

ROAS suddenly dropped? Check the dashboard's Purchase Gap Alert first — it's built for exactly this. If it's not flagging anything, check your 30-day table for a spike in errors on the affected day.

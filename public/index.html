How to import

  1. Open Web GTM → Admin → Import Container → upload web.json. Choose Merge.
  2. Import server.json into Server GTM → Merge. The GA4 forwarding tag and Meta CAPI tag are included.
  3. If TikTok is selected, open Server GTM → Templates → Search Gallery → add TikTok Events API.
  4. web.json now fires browser-side Meta & TikTok pixel events (ViewContent, AddToCart, InitiateCheckout, AddPaymentInfo, Purchase) stamped with the same event_id as the server CAPI hit — the platforms dedupe automatically, so you get browser + server coverage without double-counting.
  5. Preview both containers, fire a Purchase event, then verify Tagioo Event Logs, GA4 Realtime, and Meta Test Events.

dataLayer push — all events

Each event below maps to a GTM trigger in your imported template. The GA4 tag forwards everything (including user_data and ecommerce) to sGTM → Meta CAPI. Always push { ecommerce: null } before any ecommerce event to clear previous data.

window.dataLayer = window.dataLayer || [];
window.dataLayer.push({
  event:    'page_view',
  event_id: crypto.randomUUID(),   // unique per fire — required for deduplication

    first_name:    'john',              // lowercase

  }

});

// For themes without cart:add — intercept fetch to /cart/add.js
const _fetch = window.fetch;
window.fetch = function(...args) {
  const res = _fetch.apply(this, args);
  if (String(args[0]).includes('/cart/add')) {
    res.then(r => r.clone().json()).then(item => {
      window.dataLayer.push({ ecommerce: null });
      window.dataLayer.push({
        event: 'add_to_cart', event_id: item.key + '-atc',
        ecommerce: { currency: '{{ shop.currency }}',
          value: item.price / 100 * item.quantity,
          items: [{ item_id: item.sku, item_name: item.product_title,
            price: item.price / 100, quantity: item.quantity }] }
      });
    });
  }
  return res;
};

10-minute setup

WooCommerce → Tagioo in 4 steps

Follow these in order. Each step takes ~2 minutes. By the end your store sends clean, server-side, deduplicated events to GA4, Meta and TikTok — and recovers purchases even when the browser pixel is blocked.

  1. 1
    Order sync webhookNative WooCommerce webhook → Tagioo. No plugin. ~2 min.Jump to step 1 ↓
  2. 2
    Install GTM4WP pluginFree WordPress plugin that pushes the dataLayer e-commerce events. ~3 min.Jump to step 2 ↓
  3. 3
    Import GTM containersImport the two ready-made JSON files (web + server). ~3 min.Jump to step 3 ↓
  4. 4
    Test & go liveFire a test purchase and confirm it lands everywhere. ~2 min.Jump to step 4 ↓
Step 1 — order sync (no plugin) WooCommerce native webhook — built into every WordPress store, nothing to install
  1. In your WordPress admin, go to WooCommerce → Settings → Advanced → Webhooks and click Add webhook.
  2. Fill the form exactly like this:
Name:          Tagioo order sync
Status:        Active
Topic:         Order created
Delivery URL:  https://your-panel-domain/api/orders/woocommerce
Secret:        click “Generate secret” below
API Version:   WP REST API Integration v3
  1. Click Save webhook. WooCommerce sends a test ping — the status should stay Active.
  2. Place a test order. It appears in your Tagioo dashboard within seconds and is matched against tracked purchases automatically.

Generating a new secret replaces the old one, so update the WooCommerce webhook if you regenerate. Tagioo verifies every delivery with the x-wc-webhook-signature header, so no plugin, code snippet, or API key is needed on your site. Order ID, total, currency, and date are mapped automatically.

Step 2 — install GTM4WP Free plugin that pushes WooCommerce e-commerce events into the dataLayer — no code
  1. In WordPress admin go to Plugins → Add New, search “GTM4WP” (by Thomas Geiger), then Install and Activate.
  2. Open Settings → Google Tag Manager and enter your web container ID in General → Google Tag Manager ID (format GTM-XXXXXXX). Set Container code placement to Codeless / off only if you load GTM yourself; otherwise leave On.
  3. Open the Integration → WooCommerce tab and turn ON these settings:
✅ Track enhanced e-commerce          (master switch)
✅ Track classic e-commerce            OFF — use enhanced only
✅ purchase / view_item / add_to_cart / begin_checkout / view_item_list
✅ Use new GA4 ecommerce data structure   ← REQUIRED (items[], not products[])
✅ Include tax in product price        (match your GA4 / Meta value)
✅ Send user data (email, phone) on order   ← powers Meta CAPI / Google EC matching

The “new GA4 ecommerce data structure” toggle is the one people miss — without it events arrive in the old Universal Analytics shape and Tagioo’s GA4/Meta tags won’t read the items array. Save changes. GTM4WP now pushes view_item, add_to_cart, begin_checkout and purchase automatically — you can skip the manual PHP snippets at the bottom of this page.

Step 3 — import GTM containers Two ready-made JSON files: one web container, one server container
  1. Download the two container files generated for your store using the buttons in the “Container templates” panel above (Web container JSON + Server container JSON).
  2. Web container: open tagmanager.google.com → your web container → Admin → Import Container. Choose the web JSON, pick Existing workspace, and select Merge → Overwrite conflicting tags. Click Confirm.
  3. Server container: switch to your server container → Admin → Import Container, choose the server JSON, Merge → Overwrite, Confirm.
  4. In the server container open Clients and confirm the GA4 client and the Data tag point to your tracking domain.
  5. Click Submit → Publish on both containers.

The JSON files already contain the GA4, Meta CAPI and TikTok tags, all triggers, and the variables that read GTM4WP’s dataLayer — including transaction_id for deduplication. You only fill in your own pixel/measurement IDs, which are pre-populated from the form above.

Step 4 — test & go live Confirm one real purchase reaches every destination, then you’re done
  1. In each GTM container click Preview and enter your store URL to open Tag Assistant.
  2. On your store: view a product, add to cart, begin checkout, and place a test order (a 1-unit cheap product or 100% coupon).
  3. In Tag Assistant confirm view_item, add_to_cart, begin_checkout and purchase fire, and that the GA4 / Meta / TikTok tags fired on purchase.
  4. Verify the event landed everywhere:
    • Tagioo → Event Logs: the request appears within seconds; the Purchase Inspector shows the order with its transaction_id.
    • GA4: Reports → Realtime shows the purchase with revenue.
    • Meta: Events Manager → Test Events shows Purchase (server) — and no duplicate vs the browser pixel, because both share transaction_id.
  5. Refund/cancel the test order. Done — your store is now tracking server-side. 🎉

Seeing duplicate purchases in Meta? Make sure the browser pixel and the CAPI/server tag both send the same event_id/transaction_id (the order ID). Tagioo and the supplied containers already do this — duplicates almost always mean a second, older pixel is still hard-coded in your theme.

Pre-launch checklist

  • □ user_data pushed on every event — not just purchase. PageView, ViewContent, AddToCart, InitiateCheckout all need it for session-level match.
  • □ event_id is unique per event — use crypto.randomUUID() or Date.now() + Math.random(). Prevents deduplication errors between Pixel and CAPI.
  • □ Phone in E.164 format — must start with + and country code. +8801700000000 not 01700000000.
  • □ Names lowercase — send john not John. Meta normalises before hashing; mismatches reduce match rate.
  • □ external_id consistent — use the same user ID you use in your CRM. Must be identical across browser and server events.
  • □ AddToCart must include user_data — commonly missed. Push it even for guest users if phone/email was collected at any point in the session.
  • □ Test in Meta Events Manager — use Test Event Code to verify all parameters arrive hashed and the score reaches 8+.

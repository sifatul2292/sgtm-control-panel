How to create a container

Four steps, no code required.

  1. Point a subdomain at Tagioo Create a subdomain like server.yourdomain.com, then add a CNAME record in your domain's DNS: Host = your subdomain, Value = bd.tagioo.com.
  2. Copy your GTM container config In Google Tag Manager: Admin → Container Settings → Manually provision tagging server. Copy the full value shown there.
  3. Fill in the form Enter the website, the same subdomain, and paste the config exactly as copied.
  4. Create the container Tagioo launches Docker, Nginx, and SSL automatically — no server access needed.

How to import

  1. Open Web GTM → Admin → Import Container → upload web.json. Choose Merge.
  2. Import server.json into Server GTM → Merge. The GA4 forwarding tag and Meta CAPI tag are included.
  3. If TikTok is selected, open Server GTM → Templates → Search Gallery → add TikTok Events API.
  4. web.json now fires browser-side Meta & TikTok pixel events (ViewContent, AddToCart, InitiateCheckout, AddPaymentInfo, Purchase) stamped with the same event_id as the server CAPI hit — the platforms dedupe automatically, so you get browser + server coverage without double-counting.
  5. Preview both containers, fire a Purchase event, then verify Tagioo Event Logs, GA4 Realtime, and Meta Test Events.

Website DataLayer Setup

Push these events and user_data fields from your website to achieve maximum event match quality. All fields are hashed server-side — send them plain.

dataLayer push — all events

Each event below maps to a GTM trigger in your imported template. The GA4 tag forwards everything (including user_data and ecommerce) to sGTM → Meta CAPI. Always push { ecommerce: null } before any ecommerce event to clear previous data.

page_view GTM trigger: DOM Ready · fires on every page load 
window.dataLayer = window.dataLayer || [];
window.dataLayer.push({
  event:    'page_view',
  event_id: crypto.randomUUID(),   // unique per fire — required for deduplication
  user_data: {                     // push whenever user session has this data
    email_address: 'user@example.com',  // lowercase
    phone_number:  '+8801700000000',    // E.164 with country code
    first_name:    'john',              // lowercase
    last_name:     'doe',               // lowercase
    external_id:   'user_12345'         // your DB / CRM user ID
  }
  // no ecommerce object on page_view
});

// For themes without cart:add — intercept fetch to /cart/add.js
const _fetch = window.fetch;
window.fetch = function(...args) {
  const res = _fetch.apply(this, args);
  if (String(args[0]).includes('/cart/add')) {
    res.then(r => r.clone().json()).then(item => {
      window.dataLayer.push({ ecommerce: null });
      window.dataLayer.push({
        event: 'add_to_cart', event_id: item.key + '-atc',
        ecommerce: { currency: '{{ shop.currency }}',
          value: item.price / 100 * item.quantity,
          items: [{ item_id: item.sku, item_name: item.product_title,
            price: item.price / 100, quantity: item.quantity }] }
      });
    });
  }
  return res;
};

Step 1 — generate JSON files Use the Setup Assistant wizard above — fills your credentials, generates import-ready GTM files
  1. Scroll up to the Setup Assistant panel on this page.
  2. Step 1: Select Ecommerce as business type, WooCommerce as platform, set your currency and tracking domain.
  3. Step 2: Choose destinations — GA4, Meta CAPI, Google Ads, TikTok.
  4. Step 3: Enter pixel IDs, measurement IDs, and access tokens. Leave any blank — Tagioo adds placeholders you can fill inside GTM later.
  5. Step 4: Click Generate templates. Two buttons activate: ⇣ web.json and ⇣ server.json. Download both files.

These JSON files contain all GA4, Meta CAPI, and TikTok tags pre-wired to the Tagioo plugin’s dataLayer format, including transaction_id for deduplication. Keep them — you’ll import in step 3.

Step 2 — install Tagioo plugin Our WordPress plugin pushes the full ecommerce dataLayer automatically — no code, no GTM4WP needed
tagioo-woocommerce.zip
WordPress plugin · replaces GTM4WP

  1. Click Download Plugin above to get tagioo-woocommerce.zip.
  2. In WordPress admin go to Plugins → Add New → Upload Plugin, choose the zip, click Install Now, then Activate.
  3. Done — no configuration needed. Plugin automatically pushes page_view, view_item, add_to_cart, begin_checkout, purchase, and user_data on every event.

Plugin uses GA4 ecommerce structure (items[]) and includes event_id on every event for browser↔server deduplication.

Step 3 — import GTM containers & test Import web.json + server.json → publish → fire test purchase → verify in Meta
  1. Web container: open tagmanager.google.com → your web container → Admin → Import Container. Choose web.json, pick Existing workspace, select Merge → Overwrite conflicting tags. Click Confirm.
  2. Server container: switch to your server container → Admin → Import Container, choose server.json, Merge → Overwrite, Confirm.
  3. In server container open Clients — confirm GA4 client and Data tag both point to your tracking domain.
  4. Click Submit → Publish on both containers.
  5. In each container click Preview, enter your store URL, open Tag Assistant.
  6. On your store: view a product, add to cart, checkout, place a test order (cheap product or 100% coupon).
  7. Verify purchase landed:
    • Tagioo → Event Logs: purchase within seconds with transaction_id.
    • GA4 Realtime: purchase with revenue.
    • Meta → Events Manager → Test Events: Purchase server-side, no browser duplicate.
  8. Refund the test order. Store is now live with server-side tracking. 🎉

Seeing Meta duplicates? Both pixel and CAPI tag share the same event_id/transaction_id — Meta auto-deduplicates. Persistent duplicates mean an old pixel is hard-coded in your theme.

  if (get_post_meta($order_id, '_tagioo_purchase_fired', true)) return; // fire once only
  update_post_meta($order_id, '_tagioo_purchase_fired', '1');

  $order = wc_get_order($order_id);
  $ud = [
    'email_address' => strtolower($order->get_billing_email()),
    'phone_number'  => $order->get_billing_phone(),
    'first_name'    => strtolower($order->get_billing_first_name()),
    'last_name'     => strtolower($order->get_billing_last_name()),
    'external_id'   => (string) $order->get_customer_id() ?: $order->get_billing_email(),
  ];
  $items = [];
  foreach ($order->get_items() as $item) {
    $p = $item->get_product();
    $items[] = [
      'item_id'   => $p ? ($p->get_sku() ?: $p->get_id()) : $item->get_product_id(),
      'item_name' => $item->get_name(),
      'price'     => (float) wc_format_decimal($order->get_item_total($item, false, true), 2),
      'quantity'  => $item->get_quantity(),
    ];
  }
  echo "<script>
window.dataLayer.push({ ecommerce: null });
window.dataLayer.push({
  event:     'purchase',
  event_id:  'order-" . $order_id . "',
  user_data: " . wp_json_encode($ud) . ",
  ecommerce: {
    currency:       '" . $order->get_currency() . "',
    value:          " . wc_format_decimal($order->get_total(), 2) . ",
    transaction_id: '" . $order_id . "',
    items:          " . wp_json_encode($items) . "
  }
});</script>";
}, 10);

Pre-launch checklist

  • □ user_data pushed on every event — not just purchase. PageView, ViewContent, AddToCart, InitiateCheckout all need it for session-level match.
  • □ event_id is unique per event — use crypto.randomUUID() or Date.now() + Math.random(). Prevents deduplication errors between Pixel and CAPI.
  • □ Phone in E.164 format — must start with + and country code. +8801700000000 not 01700000000.
  • □ Names lowercase — send john not John. Meta normalises before hashing; mismatches reduce match rate.
  • □ external_id consistent — use the same user ID you use in your CRM. Must be identical across browser and server events.
  • □ AddToCart must include user_data — commonly missed. Push it even for guest users if phone/email was collected at any point in the session.
  • □ Test in Meta Events Manager — use Test Event Code to verify all parameters arrive hashed and the score reaches 8+.
